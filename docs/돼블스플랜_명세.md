# 돼블스플랜(승부 예측) 기능 명세 — 2026-11-14 확정 (증권 연출·역배 포인트 추가)

다승왕 앱(C:\dev\badmintion, GitHub Pages + Supabase)에 매주 승부 예측 기능을 추가한다.
지금은 밴드 투표 + 댓글로 받고, 적중자가 "+3"을 직접 댓글로 달면 돼장이 손으로 승수에 반영한다. 이걸 앱 안에서 제출 → 마감 → 자동 채점 → 승수 반영까지 처리한다.

## 규칙 (돼장 확정, 근거: 2026-11-11 단톡·밴드)
| 항목 | 규칙 |
|---|---|
| 참여 | 자율. 앱 선수 명단에 있는 사람 누구나(화목반 포함, 명단에 이미 있음) |
| 방식 | 1인 1방식: **하이리스크** 또는 **안전형** |
| 선택 | 그 주 경기 중 **서로 다른 4경기**를 골라 각각 이길 팀 선택 (같은 경기 중복 불가) |
| 본인 경기 | 예측 가능 |
| 채점 | **4경기 모두 맞혀야 적중**. 1경기라도 틀리면 실패 |
| 하이리스크 | 적중 **+3승**, 실패 **-1승** |
| 안전형 | 적중 **+1승**, 실패 **0** |
| 반영 | 다승왕 **승수에 직접 더하고 뺌** (원소속 조 순위) |
| 마감 | **매주 수요일(그 주 경기일) 17:30 KST**. 마감 전까지 수정 가능 |

## 기본값으로 정한 것 (돼장 확인 전, 바꾸기 쉽게 상수로)
- 마감 전에는 팀별 **인원수와 비율만** 공개하고, 누가 골랐는지는 **마감 후 공개**.
- 지옥도·천국도 배정은 **공식 경기 결과로만** 정한다. 예측 보너스는 등급 계산에 넣지 않는다.
- 예측한 경기가 취소되거나 결과 없이 끝나면 자동 처리하지 않고 "확인 필요"로 표시. 돼장이 관리 화면에서 처리.

## 화면
1. **예측 탭** (탭 바에 추가, 그 주 편성이 공개된 주에만 활성)
   - 이름 선택(기존 `ddw-me` 재사용) → 방식 선택 → 경기 카드에서 팀을 눌러 4개 선택 → 제출
   - 마감 시각 카운트다운("마감까지 2시간 14분"). 마감 후에는 읽기 전용
   - 내 제출 내용은 이 기기 localStorage에도 보관해서 다시 열었을 때 보여 줌
2. **실시간 인기 픽** (예측 탭 상단, 증권 앱 '많이 산 종목' 같은 순위)
   - 팀(경기의 한쪽)별 선택 인원 순위, 경기 안 비율 막대, 제출되면 실시간 갱신
   - 하이리스크/안전형 필터
3. **예측 결과 / 예측왕 순위**
   - 경기 결과가 들어오면 각자 적중/실패/대기 자동 표시. 마감 후 전원 예측 공개
   - 시즌 누적 보너스 순위
4. **다승왕 순위표**: 기존 승수 옆에 **예측 보너스** 칸, 순위는 합계(공식 승 + 보너스). 동률 규칙은 기존과 동일
5. **내 기록**: 주차별 예측 내역과 보너스
6. **증권 앱 연출** (규칙 변경 없음, 클럽에서 쓰는 '상한가·작전주' 말투 그대로)
   - **체결 피드**(1단계): 제출·변경될 때마다 이름 없이 "19:02 하이리스크 · 조영재·김성곤 매수 🔥"가 흘러감
   - **배지**(1단계): 🔺상한가 = 한 경기에서 70% 이상이 고른 팀 / 🕵️작전주 = 이번 주 가장 많이 걸린 선수 1명
   - **장 마감 리포트**(1단계): 결과 입력이 끝나면 자동 생성. 📈오늘의 상한가(최다 픽인데 승) / 📉폭락주(최다 픽인데 패, "N명이 함께 날렸습니다") / 🎯역배 적중(소수 픽 승) / 💰수익왕(하이리스크 적중자). 밴드에 캡처해서 올리기 좋은 한 장짜리 카드
   - **시세판 띠**(2단계): "조영재·김성곤 62% ▲8" 흐르는 줄. 상승 빨강(--hell), 하락 파랑(--heaven) 기존 토큰 사용
   - **내 포트폴리오**(2단계): 내 4경기를 보유 종목처럼 ✓/✕/⏳, "평가: +3승 예상 (2/4 적중 중)"
   - **투자왕 순위**(2단계): 누적 보너스·적중률·주차별 작은 그래프
7. **관리(돼장)**: 그 주 제출 현황(마감 전에도 전체 보기), 예측 수정·삭제(마감 후에도 가능), "확인 필요" 처리

## 데이터 (Supabase)
지금 저장 구조(app_state 1행을 돼장 토큰으로 통째 저장)는 여러 사람이 동시에 쓰기에 맞지 않으니 예측은 따로 둔다.
- `predictions(week_date date, player_id text, mode text check (mode in ('high','safe')), picks jsonb, updated_at timestamptz, primary key(week_date, player_id))`
  - picks 예: `[{"match":"m0101","side":"a"}, ...]` 4개
  - anon 직접 INSERT/UPDATE/DELETE 불가. **SELECT는 마감 후에만**(RLS 조건: now() >= 그 주 17:30 KST)
- `prediction_counts(week_date, match_id, side, mode, n)` — anon SELECT 가능, Realtime 구독 대상(인기 픽 실시간용). 집계만 들어 있어서 이름이 노출되지 않음
- RPC
  - `submit_prediction(week_date, player_id, mode, picks)`: 마감 전인지, player_id가 app_state 명단에 있는지, 그 주 경기에 있는 match id인지, 4개 서로 다른지, side가 a/b인지 검사 → upsert → counts 갱신(같은 트랜잭션)
  - `admin_upsert_prediction(token, ...)`, `admin_delete_prediction(token, week_date, player_id)`: 마감과 무관, 토큰 검사, counts 갱신
- `prediction_events(id bigserial, week_date, match_id, side, mode, at timestamptz)` — 이름 없음. anon SELECT + Realtime(체결 피드). submit RPC가 새로 고른 픽마다 1행 기록
- `prediction_close(week_date, match_id, side, n, total, primary key(week_date, match_id, side))` — **마감 시점 비율 스냅숏(종가)**. `close_snapshot(week_date)` 함수가 마감 후 처음 호출될 때 한 번만 채움(멱등, 이미 있으면 아무것도 안 함). 마감 뒤 돼장 수정이 있어도 역배 비율은 이 값으로 고정
- 채점·보너스는 클라이언트 순수 함수로 계산(경기 결과는 app_state에 있음). 서버에 점수를 따로 저장하지 않음 → 결과를 수정하면 자동으로 다시 계산됨

알려진 한계: 로그인이 없어서 다른 사람 이름으로 제출할 수 있다. 마감 후 전원 공개 + 돼장 수정 기능으로 밴드 댓글 방식과 같은 수준으로 막는다.

## 순수 함수 (logic.js에 추가, 테스트 먼저)
- `predictionDeadline(weekDate)` → 그 날 17:30 KST의 시각
- `validatePicks(picks, week)` → 오류 목록 (4개 아님, 중복 경기, 없는 경기, 잘못된 side)
- `scorePrediction(pred, week)` → `{ status: 'pending'|'hit'|'miss'|'check', bonus }`
  - 틀린 경기가 하나라도 결과가 나오면 즉시 miss (나머지가 대기여도)
  - 4개 모두 결과가 나오고 다 맞으면 hit
  - 선택한 경기가 편성에서 사라졌거나 무효면 check, bonus 0
- `bonusByPlayer(state, predictions)` → `{ playerId: 합계 }` (공개된 주만)
- `standings`에 보너스 합산 옵션 추가 (기존 테스트 43개는 보너스가 없을 때 결과 동일)
- `popularPicks(counts, week, mode?)` → 팀별 순위 배열

## 2단계: 역배 투자 포인트 (돼장 승인 후 적용 — 승인 전에는 계산·표시만 하고 승수 반영은 끔)
기존 하이리스크/안전형 규칙과 **별도로**, 예측한 경기마다 계산한다.
| 마감 시점 내 팀 비율 | 적중 | 실패 |
|---|---|---|
| 30% 미만 (역배) | +2 | 0 |
| 30% 이상 ~ 50% 이하 | +1 | 0 |
| 50% 초과 ~ 70% 미만 (정배) | 0 | 0 |
| 70% 이상 (상한가) | 0 | -1 (폭락) |
- 비율 = 그 경기에서 내 쪽을 고른 인원 / 그 경기를 고른 전체 인원 (두 방식 합산, `prediction_close` 기준)
- 그 경기를 고른 사람이 **5명 미만이면 포인트 없음**
- 주마다 결과가 다 나오면 누적 포인트를 승수로 환산: **3포인트당 +1승, -3포인트당 -1승(1승 차감)**, 0 쪽으로 버림하고 나머지는 이월 (5 → +1승·이월 2 / -4 → -1승·이월 -1)
- 시즌 종료 시 남은 포인트는 승수에 넣지 않음(투자왕 순위에만)
- 순위표 보너스 칸은 "예측 +3 · 투자 +1"로 나눠서 표시
- 기준값(30/50/70%, 5명, 3포인트)과 승수 반영 on/off는 settings 상수로 둬서 돼장 결정에 맞게 바꿀 수 있게
- 순수 함수: `contrarianPoints(share, total, won)`, `convertPoints(prevCarry, weekPoints)` → `{ wins, carry }`
